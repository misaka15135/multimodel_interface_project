# MMFusion Ultimate - 智能多模态无障碍交互插件

## 🚀 项目简介

**MMFusion Ultimate** 是一款专门为下一代人机交互（HCI）及无障碍技术打造的**智能多模态全自启动浏览器交互插件**。该系统完美融合了**计算机视觉（CV）手势追踪、面部网格（FaceMesh）头部姿态估计**以及**混合意图语音控制引擎**。

通过创新的内部多模态事件总线 `MMFusion Bus`，插件实现了多通道输入源的**智能仲裁、冲突消除、动态权重分发与优先级降级防御**。它允许用户在无需键盘鼠标的前提下，通过头部、手势、声音的无缝协同，实现高效、高容错、跨模态的全新网页浏览体验。

---

## 🛠 核心架构与多模态融合总线 (`MMFusion Bus`)

本插件的核心设计哲学是“多模输入，高内聚，低耦合”。系统内部通过一个集中式的事件总线对所有感知模态进行统一管理。

### 1. 优先级仲裁矩阵 (Priority Matrix)
为了防止多模态并存时发生指令打架（例如：用户一边用手势向下滑动，一边转头，同时还在说话），总线建立了严格的动态优先级机制：
* **Level 3 - 语音控制 (Voice):** 最高优先级。具备全局覆盖与硬件级中断权限。
* **Level 2 - 增强手势 (Gesture):** 中高优先级。用于高频、精确的页面级交互与光标自由悬停。
* **Level 1 - 头部姿态 (Face/Head):** 基础操作模态。用于大范围页面滚动和长文本浏览。

### 2. 去重与冲突消除 (Deduplication & Conflict Prevention)
* **时间窗去重 (`DEDUP_WINDOW = 500ms`):** 在 500 毫秒的物理滑窗内，若高优先级模态已触发特定动作，总线将自动抑制低优先级模态的同类或关联动作。
* **互斥动作对 (`CONFLICT_PAIRS`):** 预先定义 `['scroll_up', 'scroll_down']`、`['go_back', 'go_forward']` 等互斥对。当两个模态同时发出方向相反的指令时，总线将自动丢弃低优先级指令，防止页面剧烈抖动。

## 💎 三大核心功能模块详解

### 1. 混合意图语音助手 ("小助手")
语音模块采用**本地硬编码关键词识别 + 远程大语言模型（LLM）语义兜底**的混合双引擎架构。
* **状态指示 UI (左上角悬浮窗):**
    * 🔴 **语音待机中 (灰色):** 系统处于超低功耗静默监听状态。提示：`请呼叫“小助手”激活语音控制`。
    * 🟢 **正在聆听 (绿色呼吸发光灯):** 唤醒成功。提示：`正在聆听`。实时通过蓝绿色斜体文字（如 *“请帮我向下滚动”*）在面板展示用户说话的转写文本。
* **1分钟智能自动休眠:** 被唤醒后，若连续 1 分钟未检测到有效控制指令，小助手将安全退出激活状态，面板提示：`超过1分钟未使用已关闭，可通过再次呼叫“小助手”激活`，释放系统计算资源。
* **核心控制指令（最高优先级硬件级拦截）:**
    * *“停止当前识别 / 关闭识别”* ➔ 相当于按下关闭控制的总开关。立即停用当前激活的摄像头硬件，画面隐藏，面板提示：`已关闭xx状态`。
    * *“开启头部/手部识别”* ➔ 状态分发路由：
        * 若全关状态：自动请求权限开启对应追踪。
        * 若已处于该状态：提示 `已处于对应状态`。
        * 若处于另一状态：无缝平滑跳转，提示 `已转至xx状态`。
* **LLM 智能兜底:** 说话未命中固定指令时，系统自动将文本打包投递至配置好的大模型 API，智能解析用户意图（如：支持理解复杂的“把网页往上拉一点”、“返回上一页”等自然语言）。

### 2. 增强手势追踪模块 (Gesture Control)
基于 **MediaPipe Hands**，全局自启动构建高精度 21 点手部动态骨骼追踪。
* **手势映射指令集:**
    * `PALM_UP` (手掌朝上) ➔ 触发页面向上平滑滚动。
    * `PALM_DOWN` (手掌朝下) ➔ 触发页面向下平滑滚动。
    * `POINT_LEFT / RIGHT` (食指指向左右) ➔ 触发浏览器前进与后退。
    * `RINGS_UP` (OK手势) ➔ 触发页面点赞/核心交互动作。
* **自由悬停模式 (Free Hover Mode):** 通过中指与无名指联合触发，生成虚拟悬停光标，实现非接触式的“隔空点按”。
* **安全紧急退出:** 监测到单小拇指（`PINKY_ONLY`）常驻时，作为物理安全网拦截，自动挂起手势识别。

### 3. 头部姿态追踪模块 (Head Control)
基于 **MediaPipe FaceMesh**，提取面部 3D 关键点，计算 Head Pitch（俯仰角）、 Yaw（偏航角）与 Mouth Ratio（张口度）。
* **动态差分滚动:** 实时计算头部上下抬起的角度差。当用户微微抬头，页面产生向上的平滑差分滚动；低头则向下滚动。
* **姿态状态指示条 (右下角面板):** 实时反馈头部俯仰的物理位置，通过安全边界锚点避免过载。
* **手势-头部模态联动切换:** 遵循特定的快捷跳转（如接收到 V字手势触发或特定摇头交互后），可在手势与头部追踪模态间无缝平滑切换。

## 🌍 多模态生态交互场景模拟（全环境落地体现）

为了体现该系统在真实世界复杂多变环境下的自适应多模态联动能力，以下列举四种极端且典型的用户使用场景：

### 🍽 场景一：居家烹饪与进食环境（双手占满/沾污 ➔ 语音主导 + 头部辅助）
* **环境挑战:** 用户在厨房看着网页上的食谱做饭，或者正坐在电脑前吃炸鸡，双手沾满油污、面粉，绝对无法触碰键盘、鼠标或做出高精度手势。
* **多模态联动表现:**
    1.  用户对着空气呼唤：*“小助手”*。左上角面板瞬间激活为**绿色呼吸状态**，显示“正在聆听”。
    2.  用户说：*“开启头部识别”*。系统响应：`已开启头部识别状态`，摄像头静默打开，面部追踪就绪。
    3.  用户在接下来的几分钟内，仅需要一边揉面团，一边**微微抬起或低下脖子**，网页便极其平滑地上下滚动食谱。
    4.  中途用户不需要看网页了，直接说一句：*“停止当前识别”*。摄像头应声关闭，系统重新归于静默。**全程不脏手，不污染设备。**

### 💻 场景二：极客深夜编程环境（双手常驻键盘 / 无法发声 ➔ 手势主导 + 自由悬停）
* **环境挑战:** 深夜在宿舍或卧室编程，家人已入睡，用户无法发出声音（不能用语音），同时双手需要高频在键盘上敲击核心代码。
* **多模态联动表现:**
    1.  由于环境安静，用户不使用语音。插件自动依靠底层的物理手势或自启动按钮常驻。
    2.  当编写完一段长代码需要查阅庞大的 API 英文文档时，用户双手离开键盘，右侧伸出右手，手掌朝下（`PALM_DOWN`），文档极其平滑地向下滚动。
    3.  当看到核心的超链接时，用户并起中指与无名指，屏幕上立刻浮现出一个炫酷的**虚拟光标**。通过物理手势隔空移动，光标精准悬停在超链接上并自动触发 `click` 动作，成功跳转。
    4.  当有误触可能时，用户竖起单小拇指（`PINKY_ONLY`），整个手势流的动作确认被安全挂起，体现极高容错性。

### ♿ 场景三：严重上肢肢体障碍（无障碍无缝关怀 ➔ 语音路由 + 头部高精差分追踪）
* **环境挑战:** 用户患有严重的上肢运动障碍（如渐冻症、高位截瘫），完全无法使用双手或进行任何有效的肢体手势，但其语言功能与头部活动能力完好。
* **多模态联动表现:**
    1.  用户面对屏幕，直接呼喊 *“小助手”*。左上角指示器变绿。
    2.  用户下达口令：*“开启头部识别”*。系统瞬间将核心感知通道切换至面部网格。
    3.  用户无需手势，通过系统特有的**两次左右摇头物理标定机制**，激活头部的高精差分滚动。
    4.  用户仅需通过下巴的轻微抬起和降低，就可以极其自如、精准、长久地浏览新闻、观看视频、上下翻页。
    5.  如果看累了需要休息，用户轻声说出：*“停止当前识别”*。摄像头光流与追踪算法立刻中止，防止对障碍用户造成不必要的面部疲劳与光流过载。

### 🎧 场景四：开放式喧闹办工场所（多路杂音干扰 ➔ 语音强固本地指令 + 手势抗干扰互补）
* **环境挑战:** 办公室人声鼎沸，背景音乐、同事说话声不绝于耳。普通的纯云端语音识别由于长句转写极易受杂音污染，导致解析失败。
* **多模态联动表现:**
    1.  用户呼唤 *“小助手”*，由于环境杂音，可能首次未成功，用户走近麦克风再次呼唤，触发唤醒。
    2.  因为插件采用了**本地最高优先级的硬编码正则关键词匹配**，当用户简短有力地说出 *“开启手部识别”* 时，系统甚至不需要将这段录音发送给大模型，在本地仅需识别到 `“开启手”` 这两个核心音素，便瞬间切入到手势识别。
    3.  一旦切入手势识别，由于手势模态完全基于视觉，物理环境的喧闹对视觉追踪产生**零干扰**。
    4.  此时即使背景有同事大喊大叫，用户依然可以通过手掌的上下翻转（`PALM_UP/DOWN`）极其稳定地控制页面。
    5.  当 `MMFusion Bus` 检测到手势模态（优先级 2）在持续稳定输出大范围动作时，会自动在后台对干扰不断的语音云端兜底请求（优先级 3 的 LLM 意图解析部分）进行物理限流与降噪挂起，避免杂音误导大模型返回错误的控制意图，实现了**环境级跨模态抗干扰防御**。

## ⚙️ 文件修改与开发指南

如果你需要基于现有项目进行二次开发或定制，请重点关注以下三个文件：

1.  **`manifest.json` (清单配置文件):** 确保声明了 `MAIN` 世界的 `world` 运行权限，保证 MediaPipe 能够正确拿到 `window.Camera` 的硬件 API。
2.  **`content.css` (视觉样式表):** 包含左下角视频预览面板、右下角状态指示面板，以及新增的**左上角语音小助手暗色系毛玻璃面板（`#voice-panel`）**的全部美化与呼吸灯动画代码。
3.  **`content.js` (多模态核心驱动脚本):**
    * **顶层区域:** 配置 `LLM_API_CONFIG` 的 API 密钥与模型端点。
    * **`MMFusion` 自定义对象:** 修改优先级权重矩阵与去重滑窗大小。
    * **`initVoiceControl()` 函数:** 基于浏览器原生 `WebSpeech API` 构建的持续无感监听器，管理唤醒词逻辑与一分钟超时计时器。
    * **`handleVoiceCommand(text)` 函数:** 核心状态路由器，在此处添加或修改本地硬编码控制口令。

## 📦 安装与配置步骤

1.  下载或克隆本项目的所有源代码文件（确保 `manifest.json`, `content.js`, `content.css` 处于同一目录下）。
2.  打开谷歌浏览器（Google Chrome），在地址栏输入 `chrome://extensions/` 并回车。
3.  在扩展程序页面右上角，开启 **“开发者模式”** 开关。
4.  点击左上角的 **“加载已解压的扩展程序”**，选择本项目所在的文件夹。
5.  打开 `content.js`，定位到文件顶部的 `LLM_API_CONFIG`，将 `key` 替换为你合法的 LLM API Token 即可开启自然语言高级意图理解功能。
6.  随意打开一个普通的 http/https 网页，允许麦克风与摄像头权限，即可开始畅享前所未有的多模态未来交互！
