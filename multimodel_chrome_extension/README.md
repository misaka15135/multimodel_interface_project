# 🌐 混合模态控制增强扩展 (Multimodal Control Extension)

这是一个基于 Chrome 浏览器的多模态交互增强扩展。本扩展打破了传统键鼠交互的限制，深度集成了**手势追踪（Hand Tracking）**、**头部/面部追踪（Head & Face Mesh）**与**大模型驱动的语音声控（LLM Voice Control）**。用户可以通过肢体语言和自然语音，实现对网页的无缝、沉浸式浏览与全方位控制。

---

## 🚀 一、 如何使用此扩展

### 1. 安装与部署

1. 下载并解压本项目源码包。
2. 打开 Chrome 浏览器，地址栏输入 `chrome://extensions/` 进入扩展程序页面。
3. 开启右上角的 **“开发者模式”**。
4. 点击左上角 **“加载已解压的扩展程序”**，选择包含 `manifest.json` 的本文件夹。

### 2. 初始化与授权

1. 随意打开一个网页（如 Bilibili 视频播放页）。
2. 页面左下角会出现 **“开启混合控制”** 按钮，点击它。
3. 浏览器会弹窗请求**摄像头**和**麦克风**权限，请点击“允许”。
4. 加载完毕后（初次加载需下载 MediaPipe 模型），即可看到左下角的摄像头调试窗口、右侧的控制面板以及左上角的语音待机悬浮窗。

### 3. 核心交互逻辑

* **默认唤醒：** 插件启动后默认进入【👐 手势模式】。
* **语音唤醒：** 任何时候只要说出 **“小助手”** 即可激活语音引擎，支持**连读**（如：“小助手向下滚动”）。

## 🧩 二、 核心板块功能详解

### 👐 1. 手势交互模式 (Hand Gesture Mode)

利用摄像头实时捕捉手部关键点，通过精准的手势识别映射浏览器行为：

* **动态映射：**
* **手心向上/向下** (`PALM_UP` / `PALM_DOWN`)：控制页面平滑上滚/下滚。
* **食指左右指** (`POINT_LEFT` / `POINT_RIGHT`)：控制视频快退/快进 5 秒。


* **瞬发动作：**
* **伸出中指** (`MIDDLE`)：视频暂停/继续播放。
* **无名指弯曲（摇滚手势）** (`RINGS_UP`)：触发页面“点赞”。
* **牛角手势** (`HORNS`)：视频倍速切换。
* **比个 V 字** (`V_SIGN`)：一键切换至【头控模式】。


* **🖱️ 自由鼠标模式：** 做出特定手势（如 OK 手势变体）可唤出红色虚拟光标，用食指在空中移动光标，悬停 1.2 秒自动触发真实点击。

### 🗣️ 2. 头部与面部追踪模式 (Head & Face Mode)

解放双手，仅凭头部姿态和细微表情即可掌控全局：

* **俯仰角 (Pitch)：** 抬头/低头控制页面的上下滚动。
* **偏航角 (Yaw)：** 头部左右偏转控制视频的快进/快退。
* **张嘴动作 (Mouth Open)：** 实时测算上下唇内侧距离，持续张嘴 2 秒触发视频的播放/暂停。
* **复合微动作：**
* **连续点头两次** (`DOUBLE_NOD`)：触发一键点赞。
* **连续摇头两次** (`DOUBLE_SHAKE`)：退出头控，切回【手势模式】。



### 🎙️ 3. LLM 智能语音控制 (Voice Control with LLM)

接入大模型意图识别引擎，将模糊的自然语言转化为精确的 DOM 操控：

* **系统级硬指令：** 无需经过大模型，极速响应“小助手，切换到头部识别”、“小助手，关闭识别”等底层硬件控制。
* **LLM 语义路由：** 支持说出类似“帮我往下翻一点”、“视频停一下”、“给个赞”等日常用语，大模型会自动将其映射为标准的页面动作。
* **🚀 智能评论双引擎 (亮点功能)：**
当用户说出“小助手，评论说视频做得很棒”时：
1. **B站原生 API 引擎：** 若检测到处于 bilibili.com，系统会隐蔽抓取防伪造 Cookie，直接向 B站后端接口发包，实现 0 延迟、防屏蔽的硬核评论。
2. **DOM 劫持兜底引擎：** 若处于其他通用网页，系统会智能模拟焦点获取、穿透前端框架（如 React/Vue）填入文字，并模拟人类真实点击发送按钮。

## 🔗 三、 板块间的深度融合与协同机制

本扩展并非三个孤立模块的简单拼凑，而是通过统一的状态机和 UI 路由器实现了深度的多模态融合：

1. **模态间的无缝接力与降级：**
* 用户可以用手势（`V字手势`）优雅切入头控模式，也能用头部动作（`连续摇头`）退回手势模式。
* **语音作为最高司令官：** 在任何模式下，用户都可以直接通过语音（“小助手切换到手部”）强制重置当前的视觉追踪模块，避免了用户手部或面部离开视野时的“死锁”现象。


2. **全局统一的防抖与冷却池 (Cooldown Pool)：**
* 无论你是通过“语音说点赞”、“点头点赞”还是“手势点赞”，底层都共享一套 `cooldowns` 时间戳。这有效避免了多模态并发时（例如边点头边说话）导致的重复触发与逻辑冲突。


3. **视觉反馈的统一路由：**
* 右侧的悬浮“动作塔”充当了全局视觉反馈中心。无论是大模型下发的意图还是手部触发的命令，都会调用统一的 `triggerInstantUI` 方法，让对应的动作格子产生“呼吸发光”或“禁用变灰”的特效，让用户清楚地知道机器当前的理解状态。

## 🌟 四、 应用场景与交互体验提升

### 场景一：无障碍网页浏览体验 (Accessibility 优先)

对于因肢体障碍（如渐冻症、手部残障等群体）无法使用传统鼠标和键盘的用户，此扩展具有极大的辅助价值。用户只需在屏幕前保持正常坐姿，仅凭借头部的微小晃动（上下左右看）、配合嘴唇动作（张嘴确定/启停），加上自然的语音口令，就能独立完成阅读资讯、刷视频、甚至在社交平台留下大段评论，**真正实现了“眼口协同”的无障碍数字生活。**

### 场景二：沉浸式的“懒人”影音时刻

在一个慵懒的周末，用户正在用平板或电脑看 B站，此时正在吃零食，双手沾满油污。

* **体验提升：** 无需弄脏键盘和屏幕。头往右偏即可快进跳过无聊片段，张嘴 2 秒即可暂停去拿饮料；看到高潮部分，对着空气说一句：*“小助手，评论说前排支持一下”*，系统瞬间在后台完成发送。全程无需触碰任何实体设备，带来极致的沉浸式“懒人”体验。

### 场景三：工作台边的多任务协同

当用户双手正在操作键盘敲击代码或处理文档时，需要参考旁边显示器上的技术文档长网页。

* **体验提升：** 不需要将右手频繁从键盘移到鼠标滚轮上，只需将掌心向上/向下翻转一下，或者直接说“小助手，往下滚”，网页便会自动响应。这极大地降低了任务切换带来的认知阻力，保持了心流状态。
